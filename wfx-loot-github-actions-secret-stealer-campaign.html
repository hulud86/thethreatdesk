wfx-loot campaign hits tens of thousands of GitHub repos to steal CI secrets

An attacker using stolen GitHub accounts probed more than 61,000 repositories and ran a secret-stealing script in over 1,800 of them, then used the loot to break into cloud accounts.

By The Threat DeskNovember 12, 2026

Security firm Aikido has uncovered a campaign it calls wfx-loot that uses stolen GitHub credentials to steal secrets from continuous integration pipelines. Activity began on Nov 10.

The scale

Aikido counted 4,837 compromised accounts that opened probe pull requests in 61,764 repositories. The malicious script actually ran in more than 1,800 of them. More than 10,000 of the probes landed in repositories the compromised accounts didn't own but could reach through collaborator or organization access. SecurityWeek separately reported the campaign targeting about 60,000 repositories.

How it works

The attacker first opens a harmless-looking pull request about dependency audit notes to test for write access. It then pushes a long shell script through an existing workflow, an npm install hook or a new workflow, and within about a minute reverts the change and deletes the run logs.

The script grabs GitHub Actions secrets, cloud and SSH credentials, shell histories and AI tool tokens. Aikido saw the attacker use them to get into AWS, Google Cloud and Azure, create long-lived AWS keys, loosen an AWS role's trust policy and forge passing status checks. Automated publishing also pushed the payload into a Packagist package and two Go module tags.

Aikido says this is likely a different actor from October's GhostAction campaign.

Who's affected

Developers and organizations using GitHub Actions, especially maintainers who publish packages to npm, PyPI, Packagist, Go or crates.

What to do

Search your repos for a wfx-docs branch, a probe pull request titled docs: dependency audit notes, and commits titled ci: refresh build cache or chore: add ci helper. If the script ran, rotate every reachable secret and undo any AWS trust policy or Azure federated credential changes.
