F5 warns of six critical BIG-IP flaws that can crash traffic in some setups

Stack buffer overflows in BIG-IP's traffic engine can be triggered without logging in when certain iRules or APM policies are used. Only hotfixes are available.

By The Threat DeskNovember 18, 2026

Alongside its NGINX fixes, F5 disclosed six critical vulnerabilities in the BIG-IP data plane on Nov 18. All six are stack-based buffer overflows in TMM, the engine that handles traffic, and all are rated 9.8.

Who is exposed

An unauthenticated attacker can crash TMM and interrupt traffic until it restarts, and F5 says code execution may be possible in some cases. The management interface is not involved. Each flaw only applies to a specific configuration:

  • CVE-2026-123637: APM per-request policies that use both the Client Information and Endpoint Security agents.
  • CVE-2026-121805: iRules using PEM::subscriber.
  • CVE-2026-120292: iRules using MR::message route with an HTTP profile.
  • CVE-2026-120285: iRules using PSC::ip_address with an HTTP profile.
  • CVE-2026-116953: iRules using GENERICMESSAGE::route.
  • CVE-2026-120722: iRules using DNS::scrape.

Some also affect BIG-IP Next for Kubernetes and BIG-IP CNF.

Fixes

There is no workaround. F5 has released engineering hotfixes, which it notes have not been through full quality testing. Customers already running a custom hotfix will need a new one from F5 support.

watchTowr researcher Sina Kheirkhah found four of the flaws and F5 found the other two. F5 says none have been exploited. The batch also included six lower-rated BIG-IP bugs, including an iControl SOAP flaw fixed in versions 21.1.0.3, 17.5.1.10 and 17.1.3.6.

Who's affected

BIG-IP, BIG-IP Next for Kubernetes and CNF customers whose virtual servers use the listed iRule commands or APM policy settings.

What to do

Search your iRules for the listed commands and review APM per-request policies. If any match, apply F5's engineering hotfix and restrict iControl SOAP and REST to trusted networks.
